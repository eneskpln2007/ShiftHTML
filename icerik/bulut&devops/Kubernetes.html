What is Kubernetes?

When an application is in its early stages, managing a few containers manually or with simple tools is quite easy. However, as the application grows, running 10, 50, 100, or even thousands of containers simultaneously may become necessary. Controlling and maintaining such a massive container network manually becomes impossible.

Kubernetes (K8s) is an open-source container orchestration platform that automates the deployment, scaling, and management of containerized applications.

Auto-Scaling Flow:
Low Traffic 3 Containers (Normal Load)
Peak Campaign Period 10+ Containers (Auto Expansion)
Traffic Normalized 3 Containers (Cost Saving)

Kubernetes automatically manages where containers will run, how many replicas there will be, and how crashed systems will recover without human intervention.

Key Features of Kubernetes

1. Container Orchestration

Kubernetes' primary role is to organize containers like an orchestra conductor. It continuously monitors the target replica count and instantly starts a new container if any crashes.

2. Auto-Scaling

When system resource utilization (CPU/RAM) or real-time visitor traffic increases, Kubernetes can automatically scale up the number of containers. When traffic drops, it scales resources back down to optimize server costs.

3. Self-Healing

When a running container crashes or stops responding, Kubernetes detects this via health checks (Liveness/Readiness probes), terminates it, and creates a new one. Even if an entire server crashes, it redistributes the workload to healthy nodes.

4. Load Balancing

All incoming requests are distributed evenly and securely among active, healthy containers via the Kubernetes Service structure, preventing any single container from getting overloaded.

5. Rolling Update

When deploying a new version of an application, the entire system is not shut down. Old containers are shut down one by one and replaced with new ones (gradual rollout) to update versions without users noticing any downtime.

6. Rollback

If an unexpected error occurs in a newly deployed version, Kubernetes allows reverting the application to the previous stable version in seconds with a single command.

7. Centralized Management

All resources such as Pods, Nodes, Services, and Secrets can be monitored and managed through a single API or the `kubectl` command-line tool.

Core Structures of Kubernetes

Pod The smallest atomic unit in Kubernetes. Runs one or more dependent containers inside.
Node Physical or virtual server machines where Pods are executed (Worker & Master).
Cluster The main Kubernetes cluster environment formed by working Nodes together.
Deployment & Service Logical layers managing Pod statuses, replica counts, and network communication with the outside world.

Advantages and Disadvantages

Advantages

  • Massive Scale Management: Seamlessly manages thousands of containers from a single center.
  • High Availability (HA): Workloads are uninterruptedly shifted to other nodes even if a server crashes.
  • Cloud Independence: Runs with the same standards on AWS, Google Cloud, Azure, or On-Premise servers.
  • Full Compatibility with Microservices: Perfect infrastructure for isolating and communicating independent services.
  • Controlled Updates: Zero-downtime releases via rolling updates and rollbacks.

Disadvantages

  • Steep Learning Curve: Dozens of terms and complex architecture like Pods, Nodes, Ingress, Secrets, and Helm.
  • Overengineering: Unnecessary resource and time waste for small, single projects.
  • Difficult Setup and Maintenance: Setting up a production-level cluster requires expertise.
  • Extra Resource Consumption: The K8s control plane consumes significant CPU/RAM on its own.
  • Security Complexity: Incorrectly configured network policies and authorizations (RBAC) create vulnerabilities.

Things to Consider When Using Kubernetes

  • A real needs analysis should be done beforehand; Docker Compose should be preferred for small projects.
  • Cluster security (RBAC, Network Policy) must be configured, and the API server should not be exposed unprotected to the outside world.
  • Sensitive data (Secrets) should not be stored as plain text; encrypted storage solutions should be integrated.
  • Accurate CPU/RAM resource limits (Requests & Limits) must be defined for each Pod.
  • A centralized logging and monitoring infrastructure (Prometheus, Grafana, ELK) must be set up.
  • YAML configurations and image versions not tested in a production environment should not be deployed directly to production.
