What is Docker?

When software is developed, source codes alone may not be enough for the application to run smoothly. The application requires a specific programming language version, libraries, database, system tools, environment variables, and custom configurations.

For example, an application running on a developer's computer may crash when moved to a server due to a different operating system kernel, Python/Node.js version, or a missing library. Docker packages the application together with all its dependencies into a lightweight "Container" to eliminate this problem.

Docker Container Packaging Formula:
Application Code + Libraries + Dependencies + Configuration ➔ Docker Container

This created container package can be run identically on a developer laptop, test server, or cloud infrastructure in milliseconds.

Key Features of Docker

1. Container Technology

Docker's primary role is to create containers that provide logical isolation. In a web project, the Web Application, MySQL database, Redis cache, and Nginx web server can run in separate containers, managed independently without affecting each other.

2. Docker Image Structure

Template packages used to create containers are called Images. An image houses the operating system layer, application codes, and dependencies. Thousands of ready-made images like Python, Node.js, Ubuntu, MySQL, and Nginx can be downloaded via Docker Hub.

3. Defining Custom Templates with Dockerfile

It is a text file specifying how the application will be compiled from scratch and how the container environment will be set up. Which base image to use, which ports to open, and which dependencies to install are coded step-by-step inside the Dockerfile.

4. Multi-Container Management with Docker Compose

In projects where multiple containers need to work together (e.g., Web + DB + Redis + Nginx), the entire microservice architecture is orchestrated through a single docker-compose.yml file.

5. Easy and Standard Deployment

The developer creates the image and pushes it to a Registry (Docker Hub, AWS ECR, etc.). The server pulls this image and takes the new version live in seconds. Manual server setup steps are completely eliminated.

6. DevOps and CI/CD Integration

In Jenkins, GitHub Actions, and GitLab CI/CD systems, code scanning and automated tests are run directly inside transient Docker containers.

Pros and Cons

Pros

  • Environment Standardization: Ends the "It worked on my machine" crisis.
  • Lightning Fast Startup: Boots up in seconds compared to virtual machines.
  • Low Resource Consumption: Saves RAM and CPU by sharing the operating system kernel.
  • Full Portability: Moves seamlessly from local computers to cloud servers.
  • Easy Scaling: Can be scaled instantly from 1 container to 10 containers according to needs.
  • Microservice Compatibility: Allows services to be developed independently of each other.

Cons

  • Learning Curve: Requires mastery of terms like Dockerfile, Volume, Network, and Registry.
  • Orchestration Complexity: With hundreds of containers, additional tools like Kubernetes become mandatory.
  • Data Persistence: Requires Volume configuration to prevent data loss when a container is deleted.
  • Security Risk: Using untrusted images or incorrect root privileges can create vulnerabilities.
  • Complex Network Management: Virtual network configuration between containers requires meticulousness.

Things to Consider When Using Docker

  • Official and reliable Docker images should be used, and regular security updates should be applied.
  • Unnecessary packages should not be added to keep the image size small, and the `.dockerignore` file should be actively used.
  • Sensitive information (API passwords, database credentials) should never be embedded into the Dockerfile or Image, but managed via environment variables (ENV).
  • In systems requiring data persistence like databases, Docker Volume or Bind Mount must be used to prevent data loss.
  • Containers should be run with restricted user privileges instead of default root privileges.
  • Unused, stopped containers and unnecessary leftover images (dangling images) should be cleaned regularly (docker system prune).
